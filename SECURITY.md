# Security

## Reporting a problem

**Please don't open a public issue for anything security-related.**

Use [Report a vulnerability](https://github.com/kevinabouhanna/speaker-keeper/security/advisories/new),
which is private and goes straight to the maintainer, or email kevin@abouhanna.com.

You'll get an acknowledgement within a few days. There's no bounty — this is a free
project maintained by one person — but you will be credited in the release notes for
the fix unless you'd rather not be.

## Supported versions

Only the latest release. Fixes ship as a new version rather than as patches to old
ones; see [docs/RELEASING.md](docs/RELEASING.md) for why there is no going backwards.

## What the risk actually is

Worth stating plainly, because it is larger than it looks for an app this small.

Speaker Keeper can install its own updates. If you turn that on, setup registers a
scheduled task that runs **as `SYSTEM`** at 03:00 every night. That task reads a
manifest from this repository, downloads the files it names, and installs them into
`C:\Program Files` — silently, with no prompt, on every machine that opted in.

So **whoever controls this repository controls what runs as `SYSTEM` on those
machines.** That is the real attack surface here, and it is bigger than any bug in the
app itself.

What stands between a bad file and those machines:

- Everything is fetched over **HTTPS**. Plain HTTP is refused, except against
  `127.0.0.1`, which exists so the update path can be tested locally.
- Every downloaded file is checked against a **SHA-256** published in the manifest, and
  the update aborts if it doesn't match.
- The manifest is **generated by a GitHub Actions workflow** from the release's own
  assets, not written by hand, so it can only ever describe files that were actually
  published.
- The workflow **refuses to publish** a manifest whose version disagrees with the
  version stamped into the binaries.

What does *not* stand between them:

- The binaries are **not Authenticode-signed.** There is no certificate, which is also
  why Windows SmartScreen warns on first run. Signing is the real upgrade here, and
  costs a few hundred dollars a year.
- The updater also ships `update.ps1` itself, which is a **plain text script**. The
  integrity checks above cover it exactly as they cover the binaries, but a malicious
  line in a script is easier to miss in review than a rebuilt executable.

The practical consequences, for anyone with push access:

- Keep **two-factor authentication** on, and treat push access to this repository as
  equivalent to administrator access on every user's PC.
- Review changes to `update.ps1`, `Setup.cs` and `.github/workflows/` with that in mind.

## If you'd rather not be part of that

Auto-update is **off unless you switch it on**, and Speaker Keeper makes no network
requests at all until you do. Leave it off and update by downloading `Install.exe`
yourself, or build from source — it takes about ten seconds and needs nothing but
Windows.
